# EnoGym 1.0.5 审查问题修复

审查基线：`a902312`（1.0.4）。本轮保留现有精简界面、导入导出和训练模型，只修复审查确认的数据保护与小组件问题。没有发布 GitHub Release。

## 修复范围

| 问题 | 处理 |
| --- | --- |
| 普通备份轮转误选其他设备的同步文件 | Android 按完整标准文件名及设备前缀筛选；未知名称不删除 |
| 未备份的本地编辑被旧快照覆盖 | 以最近成功备份的数据指纹识别本地编辑；有本地编辑或无基线时保留本地冲突，仍合入新记录 |
| 服务端并发保存相互覆盖或临时文件冲突 | 版本检查与实际写入进入同一串行队列；失败不会阻断后续写入 |
| 服务端复制图片时丢失浏览器新编辑 | 使用捕获的版本提交；发生冲突则中止、清理未引用的新文件、允许重试 |
| 默认偏好无法同步 | 明确处理序列化时省略的默认偏好，以及显式空值；不清空记录集合 |
| 媒体写入失败却接受快照 | 必需媒体完整写入后才应用；异常和缺失文件使本次同步失败，回滚本次未使用的新文件 |
| 同一照片重复复制或同名照片串用 | 根据内容生成稳定名称，复用前逐字节校验；只改写传入快照的引用，不覆盖本地不同图片 |
| 服务端失败后不再重试 | 仅在成功应用或确认无变化后记录已处理；扫描与导出串行化 |
| 桌面首次添加停留在预览 | 首次启动及离开应用时准备缓存；原生首次启用请求当前引擎刷新；普通刷新继续只处理已安装组件 |
| 超过 6 小时固定追加 3 小时并暂停 | 移除该分支，沿原始起点恢复计时，保留暂停语义和已确认组；不猜测修复旧版已保存的截短历史 |

换备份目录时清除旧目录的处理进度，选择目录与读写互斥。同步仍不是逐条记录的版本控制，冲突规则详见 `docs/OWN.md`；删除不跨设备传播。旧版本可能留下的媒体不会批量删除。
